# 实用工具完善、图鉴互通与送礼查询 Implementation Plan

> **For agentic workers:** 执行时使用 `superpowers:executing-plans`，在当前任务中按顺序完成下列任务。未经明确选择，不启动子代理。各步骤通过后更新复选框，不将计划目标当作实际完成结果。

**Goal:** 保留当前紧凑版界面，完善三个已有工具、打通资料入口，增加可信的生日与最爱礼物查询，并与物品百科提速修复统一发布。

**Architecture:** 沿用原生 JavaScript 页面模块、Express 工具接口及现有 SQLite 内容库。既有计算和进度模块保持职责不变；新增礼物数据适配与查询模块，复用现有公共工具外壳。跨页面使用稳定标识和可分享参数，不复制一套图鉴或建立新账号系统。

**Tech Stack:** 项目现有 Node.js、Express、SQLite、原生 JavaScript、Tailwind CSS、Zod、Vitest、Supertest；不新增生产依赖。

**Spec:** 本文第 1—5 节为本次设计基准，第 6—9 节为实施、验收与发布计划。依据用户“把1、2、3项做了一起上线”，以及随后要求先提供正式详细方案；当前状态为待审阅，不代表已执行。

## Global Constraints

- 保持当前紧凑版本，不按旧木纹设计规范重做全站。
- 保留工作区现有物品百科性能改动，不覆盖已有修改。
- 不删除资料，不改既有 URL，不新增数据库迁移，不重置用户进度。
- 只新增必要的工具路由、读取接口和导航入口，不扩展账号、云同步或存档解析。
- 游戏规则以本站支持的 1.6.15 为核实基准，不把其他版本差异混入。
- 未核实的数据不参与肯定推荐；未收录不等于不喜欢。
- 生产数据、浏览器进度不作破坏性测试；本地采用隔离测试库与测试浏览器存储。
- 本轮方案编写不提交、不推送、不部署。实施完成后的统一发布按已授权范围执行，并在执行前说明实际命令、影响和回滚点。

## Review Focus

1. 通用礼物、类别描述、个人例外：类别不能直接扩成全部具体物品；任务 3 建立保守匹配测试。
2. 鱼名别名、同名条目与缺失目标：不得打开错误资料；任务 2 测试明确映射和无匹配降级。
3. 导入失败、用户取消、存储不可用：不得覆盖原有进度；任务 1 覆盖完整状态流。
4. 网络慢与快速切换条件：旧响应不能覆盖新结果；任务 1、4 检查错误、重试及请求竞态。
5. 非法分享参数、空结果和长名称：不得崩溃、误报或挤破布局；任务 2、4、5 覆盖。

## 3. 图鉴与工具互通设计

### 3.1 用户路径

- 鱼类详情 → “查询捕获条件” → 带入鱼名；其他条件默认不强行限制，避免排除合法捕获地点。
- 作物详情 → “计算收益” → 使用现有 `crop` 稳定 ID；季节只带合法且明确的值，保留用户调整能力。
- 社区中心条目 → “查看资料”；原有捕获查询、收益计算入口保留。
- 村民详情 → “查生日与礼物” → 定位该村民。
- 礼物查询结果 → 已发布物品详情；该物品属于鱼类或作物且有准确映射时，再提供对应工具入口。
- 工具返回资料时保留可表达的查询参数；不得无提示清空社区中心进度。

### 3.2 标识与降级规则

- 不按标题直接拼详情网址，不把图片名称当作条目标识。
- 映射以已发布条目的 `datasetSlug + entrySlug` 与工具稳定 ID 为准。
- 同名条目须用分类区分；鬼鱼与幽灵鱼分别验证，不使用模糊相似度自动绑定。
- 无唯一目标：提供带关键词的站内搜索，或仅显示文本；不能生成假详情链接。
- 关联数据通过轻量只读接口提供，不由浏览器逐页拉取 2259 条物品正文。
- 查询参数不是授权数据；服务端白名单校验，前端用 `URLSearchParams` 编码。

拟新增 `GET /api/tools/links?dataset=<分类>&entry=<条目slug>`，返回 `{ links: [{ label, href }] }`。单一详情使用一次查询；社区中心采用一次批量读取映射，禁止每个清单项单独请求。链接只能是站内已认可路径，不接受任意外部 URL。

## 4. 送礼查询第一版

### 4.1 功能与页面

- 工具首页增加第四张卡片“生日与最爱礼物查询”，不挤成四列窄卡；桌面优先两列两行，手机单列。
- “按村民查”：选择村民，显示生日、住址、已核实最爱礼物及资料入口。
- “按物品查”：输入或选择已收录具体物品，列出已确认最爱该物品的村民及生日。
- 生日支持季节筛选，按春、夏、秋、冬及游戏日 1—28 排序，不按真实日期推算游戏日期。
- 可分享参数：`villager`（村民稳定标识）、`item`（核实物品标识）、`season`（季节）。界面切换模式时清除不适用参数，刷新可恢复条件。
- 包含加载、空结果、无效参数、网络失败、数据暂缺状态。生日未知明确显示“暂未核实”。
- 页面固定提示：“仅展示已核实并收录的最爱礼物，不是完整喜恶表。未查到不代表该村民不喜欢。”

### 4.2 数据范围及核实门槛

第一版覆盖站内已发布且可正常送礼的村民；特殊不可送礼角色不混入推荐。覆盖数量在核对后以清单给出，不提前编造人数或礼物条数。

1. 盘点现有村民、生日、礼物字段与来源。
2. 优先使用用户本机原版游戏数据，结合版本一致的权威资料核对；记录来源路径或链接、版本、核实日期。
3. 具体物品精确匹配后才能反查；“宝石”等类别词不得当作一个可送的具体物品，也不默认扩为全类别。
4. 通用最爱与个人例外一起判断；不能只套通用规则。
5. 暂未能核实的关系从肯定推荐中排除，写入缺口记录，不删除原图鉴条目、不宣称“全部完整”。
6. 本次不计算赠礼品质、生日倍数、每周上限或好感点数，避免把简单查询变成未验证的数值模拟器。

### 4.3 模块与接口契约（拟新增，不是现有接口）

数据文件：`src/features/tools/data/gifts.js`。

```js
// 每条记录由核实流程生成，示例为结构定义，不是游戏事实。
// Villager: { id, entrySlug, name, birthday: { season, day } | null,
//   address, giftIds: string[] }
// Gift: { id, name, datasetSlug: string | null, entrySlug: string | null }
// Evidence: { villagerId, giftId, source, version, checkedAt }
```

纯函数：`queryGifts({ villagers, gifts }, { villager, item, season })` 返回 `{ villagers, gifts, total }`，条件按 AND 组合；空条件返回可送礼村民列表。只有核实表中的 `giftIds` 参与推荐。

`GET /api/tools/gifts` 沿用现有 `gameVersion/dataVersion` 包装，增加查询结果及 `coverage: "verified-loves-only"`。非法参数返回 400；合法但无匹配返回 200 与空结果；不返回数据库内部字段或完整物品正文。

不改变旧 API 返回格式。工具数据版本沿用项目既有版本管理办法；原图鉴新增或纠正事实时采用现有幂等种子方式，不执行清空重建。
