## 完整性的定义

1. 先从版本适用的外部集合建立逐条清单，再与站内资料比对；不能从站内已有记录反推“应有总数”。
2. 清单覆盖下面全部分类，且每条有来源、版本依据、纳入或排除理由、稳定标识。
3. 所有纳入条目都映射到正式图鉴，不用catalog或一个泛化介绍页冒充多个独立物品。
4. 所有缺项、字段待核实、图片缺失、版本不明、身份冲突均为零，才称“全量资料补齐”。
5. 资料完整、自动化验证、真实浏览器验收、上线是四个不同状态；不相互替代。

## 纳入、变体与排除

- 原版正常玩法可获得或可遭遇的内容纳入；节日、剧情、平台限定内容保留并说明条件。
- 模组、废弃/仅调试内容排除，但仍记录证据与理由，不能静默漏掉。
- 能通过正常剧情获得的临时物品不能因不能出售而排除。
- 壁纸等正常玩法可见但不能收入背包的固定样式纳入，明确“环境样式，不是可获取物品”。
- 衣服固定样式、同名不同物品ID、固定壁纸/地板图案分别计入；任意染色、品质星级、武器锻造组合、戒指组合不无限枚举，原条目解释规则。
- 不虚构官方名称；同名款式以“官方名称（款式标识）”消歧，并保存原名字段，标识必须有来源。slug不得由图片或同名文本临时猜测。
- 同一物品出现在多个来源表只登记一次；现有专题与具体物品可并存，但不能双计为两个游戏物品。

## 来源和质量

- 优先英文Wiki集合与单页，中文Wiki核对名称，版本历史确认1.6.15适用性。保存URL、页面修订号/快照摘要哈希、检查日期。
- 1.6.15之后的修改不能直接带入；页面修订时间较新不自动意味着游戏事实较新，逐项核对History及版本说明。
- 不照搬整篇Wiki，不批量复制描述；客观字段核实后使用原创中文说明并保留来源。
- 每项按类型保留真实获取、用途、限制和关联资料。没有售价写“不可出售”或“不适用”，不能用0伪装未知；没有属性的装饰物不能编造加成。
- 专用图标有来源与哈希；不使用缺省五彩碎片充当完成。环境/任务示意图须说明含义。

## 验收与安全

- 完整清单与正式条目逐条映射，缺失、重复、身份冲突、无依据排除均为零。
- 独立版本来源清单与实现分离，测试不只检查数字总数。
- 旧481条URL/内容保留，重复导入不改变旧ID；用户另加的记录不能被清理。
- 新条目SSR、API、图标与内部链接可达；相同记录不重复生成，规范URL唯一。
- 临时库执行check/build与专项测试；正式数据库不触碰。
- 新类型在360、390、430、768、1366宽度实测；视觉失败不能靠静态测试声称通过。
- 结尾检查未授权文件、CSS、package与HEAD无意外变化，暂存区为空。
