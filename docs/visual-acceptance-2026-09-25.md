## 发现与修改建议（本轮未实施）

### 1. P1：手机菜单遮挡站内搜索

- 复现：390×844 打开 `/guides` 或 `/tools/crops` → 点击“菜单” → 点击“搜索”。
- 实际：两个按钮均 `aria-expanded=true`，搜索框获得焦点，但菜单覆盖输入区。
- DOM 验证：输入框矩形 x=16、y≈103.4、宽343、高42；其中心点最上层元素实际为导航链接“攻略资料”，而非输入框。两次页面复现且截图一致。
- 影响：用户无法正常看见、点击输入框，移动导航的核心操作受阻。
- 代码依据：`public/js/app.js` 的 `mountSiteChrome()` 分别切换菜单与搜索，未互斥关闭。
- 最小建议：打开搜索时收起菜单并同步 aria-expanded；打开菜单时同样收起搜索。补双向切换、键盘焦点与三尺寸回归，不改路由或搜索逻辑。

### 2. P2：首页模组入口显示“查询 条”

- 手机与桌面分类区域均可见。
- 代码依据：`public/js/site-view.js` 首页分类卡固定在 `${Number(dataset?.entry_count) || "查询"}` 后追加“条”。
- 最小建议：真实数量与查询入口分开渲染；无数量时显示“查询”或“进入查询”，不要追加数量单位，也不能伪造模组数量。

### 3. P2：作物成熟时间格式与筛选选项不统一

- 实际示例：菠萝显示“成熟 14”，大蒜显示“成熟 4天”；成熟筛选同时出现“4”和“4天”、“6”和“6天”、“12”和“12天”。
- 影响：单位缺失，等价条件看起来像不同类别；长条件也使平板四列卡片显著增高。
- 最小建议：先统一显示层的天数单位与筛选标签；保留茶叶采收窗口、邻水稻米等完整特殊说明。筛选值合并属于逻辑变化，需单独测试确认，不能只改标签后假称相同值已合并。

### 4. P2：手机攻略目录页查找成本偏高

- 390宽列表总高约16322像素；第一篇文章标题约在页面1135像素处。核心专题在手机逐行排列，占据较长前置区域。
- 可用但不是紧凑入口。建议增加现有主题的快捷跳转或压缩专题摘要，不删除内容，不新建多余路由。

### 5. 设计符合度未通过：公共视觉与参考规范差距明显

- 本轮页面整体使用浅米色导航/页脚与低对比浅描边。虽已有游戏图标、米色底与绿色主操作，但没有落实要求的深色木纹导航/页脚、绿色 Hero 和像素装饰、深棕描边、金色按钮。
- 工具、攻略横幅右侧像素插画缺失；图鉴平板四列与规范建议两列也不一致。
- 这是设计验收差距，不是由截图拼接造成，也不意味着业务功能损坏。不能因布局未溢出便宣称已符合12张参考图。
- 建议单独安排公共主题与组件一致性收尾，先核对现有素材和锁定区域，再实施最小公共样式修改；本轮没有擅自扩为全站重做。
